FlowCheck플로우체크

논문: 트래픽 메타데이터를 활용한 IoT 기기 분류 모델의 성능 평가 및 외부 기기 적용 시 분류 경향 분석

IoT 기기 분류 결과를 받은 보안 입문자가 클래스별 건수를 입력하면, 이 앱이 논문 기준(정확도 90%, 클래스 20% 내외)으로 한쪽 쏠림(강제 분류) 경고와 해석의 한계를 보여 준다.

내 결과를 얻는 방법 4단계

  1. ① 캡처Wireshark로 약 3분
  2. ② Flow 집계scapy로 8개 특징 집계
  3. ③ 분류 실행랜덤 포레스트, 5종
  4. ④ 건수 입력클래스별 건수를 아래에
결과 파일 만드는 코드 예시 
pip install pandas scikit-learn scapy

import pandas as pd
# model: 학습된 RandomForestClassifier, X: 특징표
X = X.reindex(columns=train_columns, fill_value=0)
pd.DataFrame({"predicted": model.predict(X)}).to_csv("result.csv", index=False)

모델 학습은 논문의 설정을 따른다(논문 PDF). FlowCheck는 모델을 실행하지 않고 result.csv의 건수만 센다.

8개 특징: srcPort, dstPort, ipProto, srcNumPackets, dstNumPackets, srcPayloadSize, dstPayloadSize, flowDuration

파일이 없어도 예시로 바로 해 볼 수 있어요.

1 예시 불러오기

논문에서 학습에 없던 PC 트래픽 697 Flow를 분류했을 때의 분포입니다.

2 내 결과 입력

모델이 각 기기로 분류한 Flow 건수를 0 이상의 정수로 입력하세요. 분류 결과 CSV(predicted 열)가 있으면 아래에서 바로 집계할 수 있습니다.

CSV로 채우기 (합성 예시 데이터 — 실제 트래픽·개인정보 없음)

  • 균등(100행)다운로드
  • 약한 쏠림(100행)다운로드
  • 논문 PC 사례(697행)다운로드

파일은 이 브라우저 안에서만 처리되며 서버로 전송되지 않습니다.

3 정확도 확인

정확도는 어디서 얻나요? 모델 평가 결과의 맞힌 수 ÷ 전체 수 × 100 (논문: 12,584 ÷ 12,816).

참고: 논문 값 98.19% (12,584 / 12,816)

논문이 밝힌 해석의 한계

  1. 단일 PC에서 약 3분간 캡처한 트래픽이다.
  2. 무작위 분할을 사용해 같은 세션의 Flow가 학습·평가에 섞였을 수 있다(세션 누수 가능).
  3. 특징 기여도 분석이 없어 쏠림의 원인을 단정할 수 없다.
  4. AmazonEcho, BelkinCamera, TPLinkSmartPlug, NetatmoWeatherStation, SamsungSmartThings 5종 기기에 한정된다.

출처

  • 논문: 트래픽 메타데이터를 활용한 IoT 기기 분류 모델의 성능 평가 및 외부 기기 적용 시 분류 경향 분석 — PDF (혼동행렬 표는 PDF에만 있음)
  • 원자료: UNSW-IoTraffic(UNSW Canberra) — iotanalytics.unsw.edu.au. 이 앱에는 포함하지 않았고, 이용 조건은 해당 사이트에서 확인하세요. 인용: Sivanathan et al. (2018), "Classifying IoT Devices in Smart Environments Using Network Traffic Characteristics", IEEE Transactions on Mobile Computing 18(8), 1745–1759.
  • 모델·집계 설정: 논문 본문과 논문 재현 스크립트(Wireshark 캡처, scapy 집계, scikit-learn 랜덤 포레스트).
  • 예시 CSV 3개: FlowCheck를 위해 합성한 것입니다. 논문 PC 사례는 표의 분류 건수(392/186/100/18/1)를 라벨 목록으로 풀어 쓴 것이고, 균등·약한 쏠림은 임의 예시입니다. UNSW 원자료·실제 트래픽·식별자는 들어 있지 않습니다.
