# FlowCheck (플로우체크)

IoT 보안을 처음 배우는 사람이 기기를 눌러 보면, 이 앱이 논문의 결과(등록된 기기는 98.19%로 맞히지만, 등록되지 않은 PC 트래픽은 56.2%가 BelkinCamera 한 기기로 몰림)를 보여 준다.

기반 논문: 트래픽 메타데이터를 활용한 IoT 기기 분류 모델의 성능 평가 및 외부 기기 적용 시 분류 경향 분석

용어: **등록** = 이 모델이 학습한 IoT 기기 5종(논문 표현: 학습에 포함된 기기, 포함되지 않은 기기, 5종 안에서만 고르는 폐쇄 집합). **강제 분류** = 모르는데도 억지로 하나를 고름. **쏠림** = 한 기기로 몰림.

## 화면

포트폴리오 사이트와 같은 계열의 디자인이다(포레스트 그린 + 앰버 보조색 토큰, 알약형 버튼·링크, 둥근 카드, 격자 무늬 히어로, 다크 모드: 기본은 기기 설정을 따르고, 히어로의 「테마」 버튼으로 시스템 → 라이트 → 다크를 직접 바꿀 수 있으며 선택은 이 브라우저에 저장된다). 위에서 아래로: 히어로(한 문장) → '처음이라면 이 순서로' 3줄과 용어 풀이 → **작업 ① 등록된 기기 확인** → **작업 ② 등록되지 않은 기기(PC) 따라가기(핵심 작업)** → **작업 ③ 내 정확도 입력** → 논문의 결론 → 논문이 밝힌 한계 → 접이식 '내 결과로 확인해 보기 (선택)' → 출처. 외부 폰트·CDN은 쓰지 않는다.

## 논문 결과를 앱에서 쓰는 방법

| 작업 | 사용한 논문 수치 |
|---|---|
| ① 등록된 기기 확인 | 기기 5개를 누르면 논문 표 3(혼동행렬)에서 그 기기의 행을 읽어 "실제 N건 중 M건 맞힘(%)", 맞힘/틀림 막대, "가장 많이 틀린 상대"를 보여 준다. 상단에 전체 정확도 98.19%(12,584/12,816, §4.1)를 고정하고, 기기별 맞힌 비율 요약(SamsungSmartThings 94.19%가 가장 낮음)을 둔다. 표 2(Precision/Recall/F1/Support)와 표 3 전체는 '논문 표 전체 보기'에 있다. 논문 값만 쓰며 직접 다시 계산한 모델 값은 없다. |
| ② 등록되지 않은 기기(PC) 따라가기 | 4단계(이전/다음): 등록된 5종 → PC 트래픽 697 Flow(Windows PC 유선, Wireshark 약 3분, scapy 집계, §3.4) → 결과 BelkinCamera 392(56.2%), AmazonEcho 186(26.7%), SamsungSmartThings 100(14.3%), NetatmoWeatherStation 18(2.6%), TPLinkSmartPlug 1(0.1%) → 20% 기준선(논문 가설 2의 "5종에 똑같이 나뉘면 각 20%")과 비교해 +36.2%p. 56.2%는 FPR이 아니라 논문이 정의한 "강제 분류 비율"이며 원인은 단정할 수 없다(§5.2). |
| ③ 내 정확도 입력 | 논문 가설 1 기준(정확도 90% 이상). 참고값 98.19%(12,584/12,816). |
| 결론·한계(항상 표시) | 결론: Unknown 분리 기준, 시간·세션 기준 검증, 특징 기여도(XAI) 분석이 필요하다(§5.1·§5.2·§5.3·§6). 한계: 단일 PC·약 3분 캡처 / 무작위 분할로 세션 누수 가능 / 특징 기여도 분석 없어 쏠림 원인 단정 불가 / 5종 기기 한정. |

모델 학습·추론은 하지 않으며, 논문에 없는 기준(예: Unknown 판정 임계값)은 만들지 않았다. 앱은 등록되지 않은 기기를 가려내는 기능을 제공하지 않는다.

### 선택 영역: 내 결과로 확인해 보기 (기본 닫힘)

내 모델의 분류 결과가 있을 때만 쓴다. 4단계 가이드(캡처 → Flow 집계 → 분류 실행 → 건수 입력), 결과 파일 만드는 코드 예시, 분류 결과 건수 직접 입력 또는 CSV(`predicted` 열; 다른 열은 무시) 불러오기 → 점유율과 20%±10%p 비교(±10%p는 '내외'의 앱 내 해석이며 논문 수치가 아님). 5종 밖의 클래스명은 "알 수 없는 클래스 N건"으로 표시하고, 헤더 없음·빈 파일·5MB 초과는 안내 문구를 보여 준다. 파일은 브라우저 안에서만 처리되며 서버로 전송되지 않는다. 쏠림 점검은 등록되지 않은 기기의 트래픽 분류 결과용이다.

## 실행 방법

- `index.html`을 더블클릭해 브라우저로 연다. 또는
- 이 폴더에서 `npx serve`를 실행한 뒤 표시된 주소로 접속한다.

빌드·서버·API 키·외부 CDN이 필요 없다. 환경 변수는 없다. Vercel 정적 배포(빌드 명령 없음, 루트 폴더 그대로)로도 동작한다.

## 사용 방법 3가지와 결과

1. **등록된 기기 확인**: 기기 버튼을 누르고(화살표 키로도 이동) 결과를 본다 → 예: SamsungSmartThings를 누르면 "실제 2,564건 중 2,415건 맞힘 (94.19%)", "가장 많이 틀린 상대: AmazonEcho 126건"이 나온다.
2. **등록되지 않은 기기(PC) 따라가기**: 「다음」을 3번 눌러 4단계 끝까지 간다 → BelkinCamera 392건(56.2%), 20%보다 +36.2%p, "한 기기로 몰림" 경고가 나온다. 마지막 단계의 「처음부터」로 되돌린다.
3. **내 정확도 입력**: 정확도(%)를 입력하고 「확인」을 누른다 → 98.19는 "통과", 85는 "미달". 빈칸·문자·0~100 밖은 입력칸 아래에 안내 문구가 나오고 앱은 멈추지 않는다.

## 테스트 자료 (`samples/`)

`sample_paper_pc.csv`: 논문 표 4의 PC 트래픽 697 Flow 분류 건수(BelkinCamera 392 등)를 라벨 목록으로 푼 **합성** 파일(헤더 `predicted`, 한 줄에 클래스명 하나). 선택 영역의 「바로 불러오기」나 다운로드로 쓴다. 실제 트래픽·IP·MAC·식별자는 없다. 자세한 설명은 `samples/README.md`.

## 출처와 이용 조건

- 논문: 트래픽 메타데이터를 활용한 IoT 기기 분류 모델의 성능 평가 및 외부 기기 적용 시 분류 경향 분석 (PDF: https://kms-portfolio-site.vercel.app/assets/논문_김민석_T10.pdf). 화면의 98.19%, 표 2·3, 56.2%와 PC 사례 건수는 이 논문의 값이다.
- 원자료(논문이 쓴 데이터): UNSW IoT traffic data with packets, flows, and protocols — Wannigama, S.; Sivanathan, A.; Habibi Gharakheili, H. (2025), Dryad, DOI 10.5061/dryad.w0vt4b94b, 라이선스 CC0 1.0. 관련 논문: Sivanathan et al. (2018), "Classifying IoT Devices in Smart Environments Using Network Traffic Characteristics", IEEE Transactions on Mobile Computing 18(8), 1745–1759. 논문 때 받은 flows.zip과 Dryad flows.zip의 SHA-256이 동일함을 확인했다. 앱에는 원자료를 넣지 않았다.
- 모델·집계 설정(Wireshark 캡처, scapy Flow 집계, scikit-learn 랜덤 포레스트): 논문 본문과 논문 재현 스크립트.
- 예시 CSV: 논문 PC 사례 1개(합성, 표 4의 건수). 실제 트래픽·식별자 없음.
- 그림: 직접 만든 인라인 SVG. 외부 이미지·폰트·CDN 없음.
- CSV 집계는 코드 라벨(TPLinkPlug, NetatmoWeather, SmartThings)도 논문 표기로 인식한다.
